22a단계: 언리얼 '리비전 컨트롤(Source Control) 프로바이더' C++ 플러그인이 붙을 수 있게 데몬 HTTP API 를 보강한다(이번 단계는 파이썬만, C++ 는 22b 부터). 배경: 다음 단계에서 ISourceControlProvider 를 구현한 에디터 플러그인이 데몬(http://127.0.0.1:<port>)과 통신해 콘텐츠 브라우저 상태 아이콘, Submit(=확정), Revert(=변경 버리기), History, 내장 diff 를 제공한다. 웹 UI 는 그대로 유지한다. 현재 모델: baseline=마지막 확정 상태, snapshots.role fix|journal, confirm/discard, uediff.extract_version. 필요한 API: (1) POST /api/states {rels:[rel...]} (rels 가 비면 추적 대상 전체) → {head_fix:{id,message,time}|null, states:{rel:{state, tier, sha, baseline_sha, size, cls, noise}}}. state 값: 'clean'(baseline 과 동일), 'modified', 'added'(baseline 에 없고 디스크에 있음), 'deleted'(baseline 에 있고 디스크에 없음), 'untracked'(vendor 등급·ignore·Content 밖·애셋 확장자 아님), 'missing'(어디에도 없음). 이동은 added+deleted 로 풀어서 표현. 요청한 rel 만 해시하도록 효율적으로(전체 스캔은 rels 가 빌 때만, 결과는 (rel,size,mtime) 키로 짧게 캐시해 연속 호출이 가볍게). 순수 함수 api_states(store, rels). rel 은 Content 기준 슬래시 경로, 역슬래시·선행 슬래시 정규화, 경로 탈출('..')은 untracked. (2) GET /api/history?rel=<rel>&limit=50 → 그 애셋의 '확정 버전' 이력만(작업 중 기록 제외): [{id, revision(1부터 오름차순 번호), message, ts, time, sha, size, action:'add'|'edit'|'delete'}] 최신순. 기준은 fix 스냅샷의 tree 에서 그 rel 의 sha 가 직전 fix 대비 바뀐 지점. 순수 함수 api_history. (3) POST /api/extract {rel, sha} → uediff.extract_version 으로 <project>/Saved/JokateDiff/<sha8>/<파일이름> 에 풀고 {path}(슬래시 절대경로) 반환. sha 검증(16진수), 객체 없으면 404. (4) POST /api/confirm 과 POST /api/discard 에 editor_managed:bool 추가 — true 면 서버는 에디터 브릿지 호출(dirty 확인·release·reload)을 전혀 하지 않는다(언리얼의 리비전 컨트롤 흐름이 패키지 언로드·리로드를 직접 하기 때문). 사전 잠금 검사·replace 재시도·tmp 정리는 그대로. store.apply_restore 에 editor_managed 인자를 추가해 전달. discard 는 assets 가 비면 전부. (5) GET /api/ping → {ok:true, project, root(슬래시 절대경로), content(슬래시 절대경로), port, build, api:1} — 플러그인이 '이 데몬이 내 프로젝트의 것인지' 확인하는 용도. (6) 모든 새 엔드포인트는 기존 error_response 규칙(409 RestoreBlocked 등)을 따르고, docs/API.md 에 'UE 프로바이더용' 절로 문서화. (7) tests/test_provider_api.py: api_states 의 각 state(수정·추가·삭제·clean·vendor→untracked·경로 탈출·없는 파일), rels 빈 목록=전체, 자동 스냅샷이 찍혀도 state 는 baseline 기준, api_history 가 확정 버전만·revision 번호·add/edit/delete·작업 중 기록 제외, api_extract 경로와 재사용, confirm/discard 의 editor_managed=True 일 때 브릿지 요청 함수가 호출되지 않음(monkeypatch 로 editor_running=True 인 상황에서도), ping. 공통 규칙 — 검증: uv run --no-project --with pytest pytest -q 전부 통과. 경로는 슬래시만 사용(백슬래시 금지). 실제 에디터 실행 금지, C:/Users/kkkk4017/Projects/MNYS 에서 어떤 jokate 명령도 실행 금지. 편집은 Edit 도구로 파일별로, 일괄 치환 스크립트 금지. index.html 은 건드리지 말 것.
