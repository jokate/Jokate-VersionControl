18c단계(긴급 버그 수정): 에디터가 켜져 있을 때 롤백이 PermissionError 로 실패한다. 재현(실제 UE 5.7.4): 에디터가 로드해 둔 애셋을 되돌리면 jokate/store.py 의 apply_restore 가 'X.uasset.jokate-tmp' → 'X.uasset' 으로 tmp.replace 하는 순간 'PermissionError: [WinError 5] 액세스가 거부되었습니다' 가 나고, .jokate-tmp 파일이 Content 에 남는다. 원인: 에디터는 로드한 패키지의 .uasset 파일 핸들을 쓰기·삭제 공유 없이 열어 둔다(밖에서 open(path,'r+b') 와 os.rename 모두 실패). 실제 에디터에서 확인한 해결: unreal.EditorLoadingAndSavingUtils.unload_packages([pkg]) 를 호출하면 (True, Text('')) 를 돌려주고, unreal.find_package(name) 은 여전히 객체를 돌려주지만 파일 잠금은 풀려서 밖에서 쓰기·이름 바꾸기가 가능해진다. 그 뒤 파일을 덮어쓰고 기존 reload op(load_package → reload_packages(ASSUME_POSITIVE) → scan_paths_synchronous)을 하면 에디터가 새 내용을 보고 dirty 도 아니다(이 순서로 수동 실행해 롤백이 끝까지 동작함을 확인: 파일 1개 씀, 에디터 reload 1개). 수정: (1) jokate/ue/jokate_bridge.py 에 op 'release' 추가 — packages 각각에 대해 unreal.find_package 로 로드 여부를 보고, 로드돼 있으면 먼저 그 패키지의 애셋이 애셋 에디터 탭에 열려 있을 수 있으니 unreal.get_editor_subsystem(unreal.AssetEditorSubsystem).close_all_editors_for_asset(asset) 을 시도(실패해도 계속), 그다음 unload_packages 를 호출. 응답 {ok, released:[...], not_loaded:[...], failed:{패키지:사유}}. 틱(게임 스레드)에서 실행, 예외는 ok=false. (2) jokate/store.py apply_restore 의 에디터 경로 순서를 dirty 확인 → release 요청(덮어쓸 파일과 삭제할 파일의 패키지 전부) → 사전 잠금 검사 → 안전 스냅샷 → 쓰기/삭제 → reload 로 바꾼다. 사전 잠금 검사 file_locked(path): 존재하는 대상 파일을 'r+b' 로 열어 보는 방식(내용은 건드리지 않음)으로 하나라도 잠겨 있으면 아무것도 쓰지 않고 RestoreBlocked 를 던진다 — 메시지에 잠긴 파일 목록과 '에디터에서 그 애셋의 편집 창을 닫고 다시 시도' 안내, 예외에 locked 속성(목록). 에디터가 꺼져 있을 때도 같은 사전 검사를 한다(다른 프로그램이 잡고 있을 수 있음). (3) 쓰기 단계 견고화: tmp → replace 에서 PermissionError 가 나면 0.2초 간격으로 최대 5번 재시도, 그래도 실패하면 그 시점까지 쓴 파일 목록과 함께 RestoreBlocked. 어떤 경우든(성공·실패) finally 에서 이번 실행이 만든 *.jokate-tmp 를 지운다. 중간 실패 시 이미 쓴 파일이 있으면 메시지에 '안전 스냅샷 #N 으로 되돌릴 수 있음' 을 넣는다. (4) 데몬 시작 시와 Store 를 여는 CLI restore 시작 시 Content 아래의 오래된(10분 이상) *.jokate-tmp 잔여물을 정리하는 cleanup_tmp_files(cfg). scan/watch/status 는 .jokate-tmp 확장자를 원래 무시하지만(확장자가 .uasset 이 아님) 테스트로 보장. (5) web.py: RestoreBlocked 의 locked 를 409 본문에 포함, index.html 의 되돌리기 모달이 locked 목록을 dirty 목록처럼 보여준다. jokate/ue/jokate_client.py 의 format_blocked 도 locked 를 표시(에디터 확인창용). (6) revert/upload 등 다른 경로에서 Content 파일을 쓰는 곳이 있으면 같은 헬퍼를 쓰게 한다. 테스트: tests/test_store.py·test_bridge.py 에 — 가짜 브릿지가 release 요청을 받는지와 순서(dirty → release → 쓰기 → reload), release 가 실패를 돌려줘도 사전 잠금 검사로 판단, file_locked 가 참인 파일이 있으면 아무 파일도 바뀌지 않고 안전 스냅샷도 만들어지지 않으며 RestoreBlocked.locked 에 목록, replace 가 처음 두 번 PermissionError 를 내다 성공하는 경우 재시도로 성공(monkeypatch), 끝까지 실패하면 .jokate-tmp 가 남지 않음, cleanup_tmp_files, api_restore_apply 의 409 locked. jokate_bridge.py 는 python -m py_compile 로 문법 확인.
