21b단계: '확정' 중심 모델을 웹 UI·에디터 메뉴에 반영. 전제(21a): 스냅샷에 role(fix=확정 버전 | journal=작업 중 기록)이 있고, POST /api/confirm {message, only}(응답 cleared), POST /api/discard {assets, discard_dirty}(응답 undo:{id}|null, cleared), GET /api/log?role=fix|journal|all, api_info 의 fixes·journal·pending 이 있다. 확정하면 그 이전의 journal 이 전부 지워지고, 변경을 버리면 실행 취소 지점 하나만 남는다. 과거 버전으로 되돌린 결과는 journal 이며 baseline 대비 '확정 안 된 변경'으로 보인다. 목표 화면: git 클라이언트처럼 — 위에는 '작업 중(확정 안 된 변경)', 아래에는 '확정 이력'. (1) index.html 왼쪽 열 재구성: ① '확정 안 된 변경' 카드(기존 현재 변경사항 패널): 헤더에 기준 '마지막 확정 #N 이후', 목록·다중 선택·우클릭은 그대로, 카드 하단에 메시지 입력 + 큰 '확정' 버튼(선택이 있으면 '선택한 n개 확정', 없으면 '전부 확정') + 보조 '변경 버리기' 버튼(선택 또는 전부). 헤더 상단 바의 기존 '스냅샷 만들기' 입력/버튼은 제거하고 이 카드로 옮긴다. 확정 성공 토스트: '#N 확정 · 작업 중 기록 k개 정리'. ② '작업 중 기록' 서랍: 기본 접힘, 제목에 개수('자동 저장 5 · 되돌리기 1'), 부제 '확정하면 지워집니다'. 펼치면 journal 스냅샷 목록(흐린 스타일, 기존 .snap 재사용) — 클릭하면 상세, 우클릭 '이 시점으로 되돌리기'. journal 이 0개면 서랍을 숨긴다. ③ '확정 이력' 카드(기존 타임라인): role=fix 만 표시, 세로 레일·검색·다중 선택·묶기·리세이브 표시는 유지. 기존 '자동 저장 숨기기' 토글은 제거(이제 구조로 분리됨). 5초 자동 갱신은 세 영역 모두에 적용. (2) 용어 통일: 올리기→확정, 올림→확정, 올리지 않은 변경→확정 안 된 변경, 마지막으로 올린 상태로 되돌리기→변경 버리기(마지막 확정 상태로), 스냅샷(확정 이력 안에서는)→버전. 우클릭 메뉴: 변경 카드 → '선택한 것만 확정', '전부 확정', '선택한 변경 버리기'; 확정 이력 → '선택한 애셋을 이 버전으로 되돌리기', '이 버전 전체로 되돌리기'(되돌린 결과는 확정 안 된 변경으로 나타난다는 안내를 확인 모달에 추가: '되돌린 뒤 확정을 눌러야 새 버전이 됩니다'). (3) 변경 버리기 흐름: 드라이런 확인 모달(GET /api/revert 재사용) → POST /api/discard → 토스트 '변경 n개 버림 · 작업 중 기록 정리' + undo 가 있으면 '실행 취소' 버튼(10초, 누르면 POST /api/restore/<undo id> 같은 assets). (3b) 실행 취소 지점 보강(store.py·web.py 의 작은 수정 허용): 지금 discard 는 안전 스냅샷이 새로 만들어지지 않으면 undo 를 None 으로 돌려준다. 그런데 그 경우 버리기 전 상태는 apply_restore 가 돌려주는 safety(=그 시점 HEAD, 보통 직전 확정 버전의 전체 트리)에 그대로 들어 있고 확정 버전은 지워지지 않는다. 따라서 discard 결과의 undo 는 '정리 뒤에도 존재하는 스냅샷이면 항상 {id}' 로 돌려준다(새로 만든 journal 안전 스냅샷이든, 기존 fix 든). 테스트 추가: 직전 확정의 트리에 버리기 전 상태가 들어 있는 경우 undo.id 가 그 fix 이고 그것으로 restore 하면 버리기 전 내용이 복원된다.
