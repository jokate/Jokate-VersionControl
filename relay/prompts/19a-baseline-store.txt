19a단계: '올린 것'과 '자동 기록'을 분리한다 — 저장소·CLI 편(웹 UI 는 19b). 문제: 데몬이 저장 5초 뒤 자동 스냅샷을 찍으면 모든 변경이 HEAD 에 들어가 버려서 '현재 변경사항'(HEAD 대비)이 항상 비고, 사용자가 원하는 '골라서 올리기'를 쓸 틈이 없다. 자동 스냅샷은 안전망 기록이고, 사용자가 이름 붙여 올리는 것은 별개의 축이어야 한다(git 의 index/commit 과 autosave 의 관계). 설계: (1) jokate/store.py 에 baseline 테이블 추가 — baseline(rel PRIMARY KEY, sha, size, cls, deps): '사용자가 마지막으로 올린(인정한) 상태'. snapshots 테이블에 uploaded TEXT NOT NULL DEFAULT '' 컬럼 추가(JSON: [{rel, state:'added'|'modified'|'deleted'|'moved', old_sha, new_sha, old_rel?, size, cls, noise}]). 마이그레이션: 컬럼·테이블이 없으면 만들고, baseline 이 비어 있으면 가장 최근 label 스냅샷의 tree 로(라벨이 하나도 없으면 HEAD tree 로, 스냅샷이 없으면 빈 채로) 채운다. (2) Store.status() = baseline 대비 작업 트리 Diff(리세이브 noise 판정은 baseline 의 객체와 비교; baseline sha 의 객체는 항상 저장소에 있어야 한다). (3) 사용자 올리기: Store.upload(message, only=None) — pending = status(); only 가 있으면 그 rel 들만(이동은 old/new rel 둘 중 하나만 골라도 쌍으로 처리), pending 이 비면 None 반환. 스냅샷은 항상 '전체 작업 트리'로 찍고(kind=label, tree 가 HEAD 와 같아도 생성) uploaded 컬럼에 올린 항목을 기록, 객체 저장, baseline 을 그 rel 들에 대해 작업 트리 상태로 갱신(삭제는 baseline 에서 제거). 기존 snap(message, only=...) 의 사용자용 부분 스냅샷 의미(HEAD tree + 선택분)는 upload 로 대체한다. 단 롤백이 쓰는 트리 단위 부분 스냅샷(15단계: 안전·결과 스냅샷을 affected 만 담기)은 내부 함수로 남겨 그대로 동작해야 한다. (4) 자동 스냅샷(kind=auto)은 baseline 을 건드리지 않는다. 롤백(apply_restore)도 baseline 을 건드리지 않는다 — 되돌린 결과가 baseline 과 다르면 자연히 '올리지 않은 변경'으로 보이고, 같으면 깨끗해진다. (5) Store.revert_to_baseline(rels) — 지정한 애셋을 baseline 버전으로 되돌리는 계획/적용(기존 plan_restore/apply_restore 의 안전 스냅샷·dirty 차단·reload·참조 검산 로직을 재사용하도록 '대상 트리'를 직접 주입할 수 있게 리팩터링). (6) 표시용: Store.show(sid) 와 log 는 스냅샷에 uploaded 가 있으면 그것을 Diff 로 변환해 보여주고(직전 스냅샷 대비가 아니라 '이번에 올린 것'), 없으면 지금처럼 직전 대비. squash 는 묶이는 스냅샷들의 uploaded 를 rel 기준으로 합친다(같은 rel 은 첫 old_sha 와 마지막 new_sha). prune/gc: baseline 이 참조하는 sha 의 객체와 meta 사이드카는 절대 지우지 않는다. (7) CLI: status(baseline 기준), upload <project> -m 메시지 [--only rel ...] 신설, 기존 snap -m 은 upload 와 같은 동작으로 연결(하위 호환: -m 있으면 upload, 없으면 auto), revert <project> --asset rel ... [--apply] 신설. daemon·watch 의 auto 는 그대로. meta.capture_for_snapshot 훅은 upload 경로에도 연결. (8) tests/test_baseline.py: 자동 스냅샷이 여러 번 찍혀도 status 가 비지 않는다, upload(only=[A]) 뒤 A 는 status 에서 사라지고 B 는 남는다, upload 스냅샷은 tree 가 HEAD 와 같아도 생성되고 show 가 올린 항목만 보여준다, 선택분에 변경이 없으면 None, 삭제·이동 올리기, revert_to_baseline 이 A 만 baseline 으로 되돌리고 자동 스냅샷 기록은 남는다, 롤백 뒤 baseline 과 다르면 pending 으로 보인다, 마이그레이션(옛 DB → baseline 채워짐), gc 가 baseline 객체를 보존, squash 의 uploaded 병합. 기존 테스트는 새 의미에 맞게 갱신하되 롤백·noise·retention 동작은 유지. docs/ARCHITECTURE.md 에 'baseline 과 자동 기록' 절, README 의 평소 흐름·CLI 표 갱신. 공통 규칙 — 검증: uv run --no-project --with pytest pytest -q 전부 통과 + python -m py_compile jokate/ue/jokate_bridge.py. 경로는 슬래시만 사용(백슬래시 금지). 실제 에디터 실행 금지, C:/Users/kkkk4017/Projects/MNYS 에서 어떤 jokate 명령도 실행 금지. 편집은 Edit 도구로 파일별로, 일괄 치환 스크립트 금지. web.py·index.html 은 이번에 API 시그니처가 깨지지 않는 선에서 최소 수정만(본격 UI 는 19b).
