22c단계: UE 플러그인 JokateSourceControl 에 실제 작업(Submit·Revert·Delete·History·내장 diff)을 붙인다. 현재 상태(22b): ue-plugin/JokateSourceControl 은 UE 5.7.4 에서 MNYSEditor 와 함께 실제로 빌드에 성공했다(컴파일 확인 완료). 프로바이더는 Connect 와 UpdateStatus(POST /api/states)만 구현돼 있고 나머지 operation 은 '지원 안 함' 으로 Failed 를 돌려준다. 너는 컴파일해 볼 수 없으니, 지금 컴파일되는 기존 코드의 include·형식·패턴을 그대로 따르고, 첨부된 엔진 헤더(ISourceControlState.h, ISourceControlRevision.h, SourceControlOperations.h, ISourceControlProvider.h)와 Git 플러그인의 Operations/Revision/State 소스(구조 참고만, 복사 금지)를 먼저 읽어 5.7 시그니처에 정확히 맞춰라. 헤더에 없는 함수를 override 하지 말 것. 데몬 API(이미 구현됨): POST /api/confirm {message, only:[rel], editor_managed:true} → {snapshot:{id,...}|null, cleared}, POST /api/discard {assets:[rel], editor_managed:true} → {ok, written, deleted, undo}, 409 {ok:false,error,locked?:[..]}, GET /api/history?rel=&limit= → [{id, revision, message, ts, time, sha, size, action:'add'|'edit'|'delete'}] 최신순, POST /api/extract {rel, sha} → {path}, POST /api/states. 구현: (1) FJokateSourceControlRevision : ISourceControlRevision (새 파일 JokateSourceControlRevision.h/.cpp) — 필드: Filename(절대경로), Rel, Sha, RevisionNumber, SnapshotId, Description, Date, Action, FileSize. Get(InOutFilename, Concurrency): POST /api/extract 로 받은 path 를 쓰되, InOutFilename 이 비어 있으면 그 path 를 넣고, 비어 있지 않으면 그 경로로 파일을 복사(IFileManager::Copy)한다. GetAnnotated 는 false. GetRevision 은 '#<snapshot id>' 문자열, GetRevisionNumber 는 revision, GetUserName 은 'local', GetClientSpec 빈 문자열, GetCheckInIdentifier 는 snapshot id, GetBranchSource 는 nullptr. 5.7 헤더의 순수 가상 함수 전부. (2) State 에 History(TArray<TSharedRef<FJokateSourceControlRevision>>) 를 실제로 채우고 GetHistorySize/GetHistoryItem/FindHistoryRevision(int32)/FindHistoryRevision(FString)/GetCurrentRevision 등을 구현. (3) UpdateStatus 에서 operation 의 ShouldUpdateHistory() 가 참이면 파일마다 GET /api/history 를 불러 History 를 채운다. (4) CheckIn(FCheckIn): GetDescription().ToString() 을 message 로, 파일들을 rel 로 바꿔 only 로 POST /api/confirm(editor_managed true, 타임아웃 60초). 성공하면 operation 의 SetSuccessMessage(FText '확정 버전 #N · 작업 중 기록 k개 정리'), 대상 파일 상태를 Clean 으로 갱신하고 브로드캐스트. snapshot 이 null(변경 없음)이면 '확정할 변경이 없습니다' 정보 메시지와 함께 Succeeded. message 가 비면 실패 메시지 '확정 메시지를 입력하세요'. (5) Revert(FRevert): POST /api/discard {assets, editor_managed:true}. 언리얼의 리비전 컨트롤 Revert 흐름이 패키지 언로드·리로드를 직접 하므로 서버는 브릿지를 부르지 않는다. 409 면 error 와 locked 목록을 operation 의 오류 메시지로(AddErrorMessge 계열 — 5.7 의 FSourceControlOperationBase API 확인), 성공하면 상태 갱신. (6) Delete(FDelete): 대상 파일을 디스크에서 지운다(IFileManager::Delete, 읽기 전용이면 해제). 이후 POST /api/states 로 상태 갱신(baseline 에 있던 것은 Deleted, 없던 것은 캐시에서 제거). (7) MarkForAdd(FMarkForAdd): 서버 호출 없이 성공 — Jokate 는 authored 폴더의 애셋을 자동으로 추적한다. 상태만 갱신. (8) Copy(FCopy, 이름 바꾸기·이동 때 호출됨): 서버 호출 없이 성공 후 상태 갱신. (9) Sync(FSync)·CheckOut(FCheckOut)·Resolve 등 나머지는 지원하지 않음 — CanExecuteOperation 이 false 를 돌려주고 Execute 는 Failed + '로컬 전용이라 지원하지 않습니다' 메시지. (10) operation 디스패치를 정리: 이름(GetName) → 핸들러 함수 맵. 동기·비동기 실행 모델은 22b 의 방식(Async ThreadPool + AsyncTask GameThread) 유지, 게임 스레드에서 HTTP 를 기다릴 때 데드락 없는 기존 FJokateHttp 사용. (11) State 의 CanCheckIn/CanRevert/CanDelete/CanAdd 등이 위 동작과 일치하는지 재점검(Added 상태의 Revert = 파일 삭제가 되므로 툴팁에 명시). (12) 문서: README '에디터에서 리비전 컨트롤로 쓰기' 절에 Submit=확정, Revert=변경 버리기, History, Diff Against Depot, 지원하지 않는 것(Sync·CheckOut) 표를 추가. docs/ARCHITECTURE.md 갱신. 파이썬 쪽은 이번에 바꿀 필요가 없으면 건드리지 말 것(필요하면 최소한으로, 테스트 포함). 검증: uv run --no-project --with pytest pytest -q 전부 통과.
