21a단계: '확정' 중심 모델 — 저장소·CLI·API 편(웹 UI 는 21b). 배경: 지금은 자동 저장(auto), 롤백 안전 스냅샷('롤백 직전 #N'), 롤백 결과('롤백: #N'), 사용자가 올린 버전(label + uploaded)이 하나의 타임라인에 같은 급으로 쌓인다. 작업이 길어지면 변경 순서 기록이 끝없이 늘어 문제가 된다. 사용자는 git/svn 처럼 '확정한 버전만 이력으로 남고, 확정 전의 작업 순서 기록은 확정(또는 변경 버리기)하는 순간 지워지는' 모델을 원한다. 기존 개념과의 대응: 19a 의 baseline = 마지막 확정 상태, upload = 확정. 설계: (1) 스냅샷을 두 부류로 나눈다 — fix(확정 버전, 영구 이력)와 journal(작업 중 기록: 자동 저장, 롤백 안전 스냅샷, 롤백 결과). snapshots 테이블에 role TEXT NOT NULL DEFAULT 'journal' 컬럼 추가(값 'fix'|'journal'), kind 컬럼(auto|label)은 하위 호환으로 유지. 마이그레이션: uploaded 가 비어 있지 않은 label → fix, message 가 '롤백' 으로 시작하는 label → journal, 그 외 label(옛 수동 스냅샷) → fix, auto → journal. 첫 스냅샷이 하나뿐이고 fix 가 없으면 가장 오래된 label 을 fix 로. (2) 확정: Store.confirm(message, only=None) — 기존 upload 와 같은 일을 하되(전체 작업 트리 스냅샷 + uploaded 기록 + baseline 갱신 + 객체 저장, role='fix'), 이어서 '이 확정 이전의 모든 journal 스냅샷'을 delete_snapshots 로 지우고 gc 를 돌린다(부모 재연결·noise 재계산은 기존 로직). only 로 일부만 확정해도 journal 은 전부 지운다 — 확정하지 않은 애셋의 현재 상태는 디스크와 새 fix 스냅샷의 tree 에 그대로 있고 baseline 대비 '확정 안 된 변경'으로 계속 보인다. pending 이 없으면 None(아무것도 지우지 않음). upload 는 confirm 의 별칭으로 남긴다. 반환에 cleared(지운 journal 수) 포함. (3) 변경 버리기: revert_to_baseline 적용이 성공하면 journal 을 정리한다 — 이번 버리기의 안전 스냅샷(되돌리기 전 상태) 하나만 '실행 취소 지점'으로 남기고 나머지 journal(이번 롤백 결과 스냅샷 포함)은 지운다. 안전 스냅샷이 새로 만들어지지 않은 경우(대상이 HEAD 와 같았음)에는 실행 취소 지점으로 쓸 journal 이 없으므로 전부 지우고, 결과의 undo 필드를 None 으로. 남긴 실행 취소 지점은 다음 confirm 이나 다음 버리기 때 지워진다. (4) 과거 버전으로 되돌리기(plan_restore/apply_restore): 안전 스냅샷과 결과 스냅샷 모두 role='journal', kind='auto' 로 기록한다(더 이상 label 이 아님). baseline 은 건드리지 않으므로 되돌린 결과가 baseline 과 다르면 '확정 안 된 변경'으로 보이고 사용자가 확정하면 새 fix 가 된다. (5) 자동 스냅샷은 role='journal'. prune 은 journal 만 대상으로(기존 규칙 유지), fix 는 절대 자동으로 지우지 않는다. squash 는 fix 끼리만 허용(사슬에 journal 이 끼어 있으면 그것들은 같이 지움), 13b 의 라벨 보호는 '확정 버전 n개가 하나로 합쳐집니다' 확인으로 의미 유지. (6) 조회: Store.log(role=None) 필터, Store.fix_log(), Store.journal(), head_fix(). show 는 fix 면 uploaded(확정한 항목) 기준, journal 이면 직전 스냅샷 대비. (7) CLI: confirm <project> -m 메시지 [--only rel ...](upload·snap -m 은 같은 동작으로 연결), discard <project> [--asset rel ...] [--apply](revert 의 별칭, 문구 '변경 버리기'), log 는 기본으로 확정 버전만 보여주고 --all 이면 journal 포함(journal 은 들여써서 구분), status 문구는 '확정 안 된 변경'. (8) web.py: api_log 에 role 포함 + GET /api/log?role=fix|journal|all(기본 all 유지해 21b 전까지 UI 가 깨지지 않게), POST /api/confirm {message, only}(=/api/snap 과 동일 동작, 응답에 cleared), POST /api/discard(=/api/revert, 응답에 undo:{id}|null, cleared), api_info 에 fixes(확정 버전 수)·journal(작업 중 기록 수) 추가. 기존 /api/snap·/api/revert 는 새 동작으로 연결해 유지.
